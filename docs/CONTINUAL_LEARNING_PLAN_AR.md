# تطوير طريقة تعلّم Dr.Plant دون البدء من الصفر

**تاريخ إعداد الخطة:** 25 نوفمبر 2026
**الحالة:** خطة تنفيذ وتجربة بحثية أولى؛ لا يوجد نموذج جديد معتمد أو مفعّل في التطبيق.

## القرار المعماري

- الاحتفاظ بنسخة مرجعية غير قابلة للتعديل من كل نموذج وأوزانه وترتيب فئاته وإعداداته ونتائجه.
- تطوير الأوزان تدريجياً فقط عبر تجارب منفصلة وقابلة للتراجع؛ لا استبدال تلقائي للنموذج العامل.
- فصل ثلاثة أشياء: أوزان النموذج، قاعدة المعرفة الزراعية، وسجل التجارب/الأدلة.
- قاعدة المعرفة المركزية تتحدث على الخادم، ويجلب التطبيق نسخة محلية موثقة عند توفر الإنترنت. تحليل الصور يعمل على النموذج والنسخة المحلية دون استعلام شبكي وقت التحليل.
- تحديث قاعدة المعرفة لا يفرض إعادة تدريب. تحديث الأوزان يحتاج تدريباً وتقييماً وإصداراً جديداً.

## تدقيق نقطة البداية الحالية

المستودع يحتوي عدة تجارب MobileNetV3-Small منفصلة، ولا يجوز دمج أوزانها مباشرة لأنها مختلفة في المهام ومجموعات الفئات والبيانات.

### مرشح التجربة الأولى: NGLD V5

- البنية: MobileNetV3-Small، دخل 160×160، أربع فئات: Bacterial Leaf Spot وDowny Mildew وHealthy Leaves وPowdery Mildew.
- الأوزان المرجعية: `results/ngld-v5/model-output/best-model.pt`.
- SHA-256 المرجعي وقت التدقيق: `47103964b7c3c501daee3a7a206334ccaf3e3225bf02f642cc54b845a60c5c94`.
- الأداء المنشور داخل المصدر: test accuracy 74.06% وmacro-F1 66.93%، على 478 صورة اختبار.
- حدود أساسية: لا توجد معرفات نبات/كرمة/مزرعة/جلسة تصوير، والتقسيم يفصل مجموعات التشابه البصري فقط؛ تسميات المصدر لم تُراجع بواسطة خبير أمراض نبات. لذلك لا يصلح هذا المرشح لإثبات دقة حقلية أو سورية.
- القرار: يمكن استعمال صور التدريب غير المصنفة في تجربة تعلم تمثيلات ذاتي، لأن أسماء الفئات لن تستخدم كإشراف تدريبي. لا يجوز استخدام تسميات الاختبار لإجراء ضبط أو اختيار النموذج؛ تستخدم مرة واحدة في التقييم النهائي فقط.

### سبب عدم التدريب الفوري داخل الكمبيوتر السحابي

- بيئة Box الحالية لا تحتوي Python packages المطلوبة: PyTorch وTorchvision وPillow وNumPy وscikit-learn غير مثبتة.
- لا توجد CUDA/GPU مثبتة/معلنة في البيئة التي فُحصت؛ مساحة القرص الحرة قرابة 1.9 GB فقط.
- تثبيت PyTorch CPU واستخراج البيانات والتدريب هنا قد يستهلك مساحة ووقتاً دون تسريع مناسب. لذلك لم نبدأ تدريباً غير قابل للتقييم أو نغيّر الأوزان المرجعية.
- سكربت التجربة أُنشئ ليعمل في بيئة PyTorch مناسبة، ويفضل Colab GPU مجاني عند توفره، دون الحاجة إلى API مدفوع.

## التجربة الأولى: تعلم تبايني ذاتي مع تقطير معرفة النموذج السابق

الملف التنفيذي: `scripts/research/train_ngld_self_supervised_distillation.py`.

### ماذا يفعل؟

1. يقرأ صور `train` فقط من manifest المدقق؛ لا يستخدم أسماء الفئات كهدف تدريبي.
2. ينشئ عرضين بصريين معتدلين للصورة نفسها (قص محدود، انعكاس أفقي، دوران محدود، تغييرات لونية خفيفة).
3. يتعلم الطالب تمثيلات أكثر ثباتاً باستخدام contrastive loss بين العرضين.
4. يحتفظ بنموذج المعلم الأصلي مجمداً ويستخدم knowledge distillation للمحافظة على سلوكه التصنيفي السابق.
5. يفتح آخر كتل MobileNet مع المصنف فقط افتراضياً، ويترك الطبقات المبكرة مجمدة لتقليل الانجراف.
6. يحفظ مرشحاً جديداً في مجلد منفصل، ولا يكتب فوق المعلم.
7. بعد انتهاء التدريب فقط، يقارن المعلم والطالب مرة واحدة على test split ويصدر فرق الدقة وmacro-F1 والتقرير التفصيلي.

### طريقة التشغيل في بيئة PyTorch (يفضل GPU مجاني عند توفره)

بعد استخراج أرشيف NGLD، اجعل `image_root` هو المجلد الذي يحتوي مباشرة مجلدات الفئات الأربع. في نسخة الأرشيف الحالية يكون عادة مجلد `Grapes Disease Dataset` داخل المجلدات المتداخلة. ثم:

```bash
pip install -r requirements-training.txt
python scripts/research/train_ngld_self_supervised_distillation.py \
  /path/to/Grapes\ Disease\ Dataset \
  results/ngld-v5/training-manifest.csv \
  results/ngld-v5/model-output/best-model.pt \
  --out results/ngld-v5-ssl-distill-v1 \
  --epochs 8 --batch-size 32 --unfreeze-last-blocks 2
```

يفحص السكربت SHA-256 لكل صورة في manifest، ومصدرها وترخيصها، ومجموعات الفصل، وترتيب الفئات قبل التدريب. قد تحتاج بيئة CPU إلى خفض `--batch-size` إلى 8 أو 16؛ لا تبدأ تشغيل CPU طويل إذا كانت بيئة GPU المجانية متاحة.

### لماذا هذه التجربة أولاً؟

إنها تختبر فرضية محددة: هل يمكن تحسين ثبات التمثيلات البصرية من صور غير مصنفة مع الحفاظ على سلوك المصنف الذي تعلمناه سابقاً؟ إنها خطوة آمنة نسبياً لا تتطلب اختراع تسميات أمراض جديدة، وتفصل بوضوح بين التعلم من الصور وبين الادعاء بمعرفة تشخيصية جديدة.

### قيود يجب عدم تجاوزها

- هذه تجربة تمثيلات، وليست دليلاً على أن النموذج أصبح يفهم مرضاً لم يره.
- تقطير المعلم يحافظ على سلوكه، لكنه قد يحافظ أيضاً على أخطائه؛ لذلك لا يعد بديلاً عن التسميات الخبيرة.
- NGLD مصدر هندي واحد، والتقسيم الحالي ليس مستقلاً بيولوجياً حسب المزرعة/النبات/الجلسة.
- لا تدمج المرشح في التطبيق، حتى لو تحسنت أرقام الاختبار الداخلي.
- لا تُعدّل `best-model.pt` الأصلي ولا تحذف الأرشيف أو manifests أو الأوزان المرجعية.

## بوابة قبول المرشح

لا يُقبل المرشح إلا إذا:

- اكتمل التدريب دون أخطاء وحُفظت الإعدادات وhash للمعلم والـ manifest.
- لم تتراجع دقة الاختبار أو macro-F1 عن المعلم، ولم تظهر خسائر كبيرة لفئة بعينها.
- اجتاز اختبار الاحتفاظ بالقدرات القديمة واختبارات صور جديدة من مصادر مستقلة.
- أضيفت لاحقاً صور سورية حقلية مع provenance ومراجعة خبير ومجموعات مستقلة.
- بقي النموذج قادراً على الامتناع عن التشخيص عند الحالات غير المعروفة أو غير الواضحة.

حتى بعد نجاح هذه التجربة، تبقى الخطوة التالية اختباراً مستقلاً على بيانات من مزارع ومناطق ومواسم وأجهزة تصوير مختلفة. لا ترفع حالة النموذج إلى الإنتاج قبل اجتياز التحقق الحقلي والمعايرة وعقد الإدخال/الإخراج.

## مراحل لاحقة بعد التجربة الأولى

1. إضافة بيانات نباتية غير مصنفة من مصادر متعددة بعد تدقيق الترخيص والتكرار والمصدر، لا مجرد جمع صور عشوائية.
2. مقارنة replay مع distillation وEWC على مهمة تعلم لاحقة، مع اختبار النسيان لكل محصول/فئة.
3. اختبار Domain Generalization على صور الحقل مقابل صور الخلفيات المضبوطة.
4. إضافة بيانات مورفولوجيا موثقة كمهام/إشارات منفصلة عن تشخيص الأمراض.
5. دراسة نموذج بصري-لغوي مفتوح الأوزان فقط إذا أثبتت اختبارات التعميم أن CNN الحالي لا يكفي؛ لا نستبدل النموذج الحالي لمجرد حداثة نموذج آخر.
