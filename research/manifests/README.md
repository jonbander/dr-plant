# Research split manifests — templates only

These three CSVs are **empty schema templates**, not evidence that any dataset has passed a leakage audit. Do not fill unknown identifiers with guessed values. A manifest is ready for validation only after each row identifies the original image, its dataset, a biologically/operationally defensible group, the source, the label, and the split.

## Files

- `templates/grape.csv`: `group_id` must be a verified vineyard/block identifier. A cultivar, image filename, camera ID, or dataset name is not a substitute for vineyard identity.
- `templates/citrus.csv`: `group_id` must be a verified tree identifier. The Citrus Field V3 source manifest uses `tree_id`; retain its original value and provenance.
- `templates/tomato.csv`: `group_id` must be the source/site/acquisition group chosen for the intended generalization claim. `source_id` records the dataset/provider lineage. Do not split images from one indivisible source across train/val/test merely to fill all three partitions. An external test set may be held out as a separate evaluation manifest.

## Column meanings

- `dataset_id`: stable dataset key matching `research/data-audit.csv`.
- `image_path`: path relative to a declared dataset root; must resolve to the exact source image.
- `sha256`: SHA-256 of the exact image bytes (exact-duplicate detection only).
- `phash`: perceptual hash generated by a documented algorithm/version; similarity requires a separate Hamming-distance audit. It is not interchangeable with SHA-256.
- `group_id`: vineyard/tree/source-site grouping unit appropriate to the claim.
- `source_id`: source dataset, provider, collection, or acquisition lineage.
- `crop`, `label`: crop and verbatim source label; do not silently normalize or merge labels.
- `split`: `train`, `val`, `calibration`, or `test`.
- `annotation_type`, `annotation_ref`: annotation kind and exact source file/record; use `image`, `bbox`, `leaf_mask`, or `lesion_mask` as appropriate.
- `license_ref`: path to the archived license record for this dataset.

## Validation

The templates intentionally contain only headers and must fail closed as empty manifests. Populate them from source manifests, then run `scripts/research/verify-splits.py` with the correct group column and `--hash-col sha256`. Use `--source-col source_id` only when the evaluation protocol requires source-disjointness. Exact SHA-256 checks do not detect resized/cropped near-duplicates; run the separately versioned perceptual-hash audit and record its report before marking `leakage_check=PASS`.

A tool PASS certifies only the supplied columns and rows. It does not certify that the identifiers are true, complete, or scientifically appropriate. Do not claim 70/15/15 ratios where group counts make that split infeasible; keep the test groups independent and report actual group/image counts.

## Safe extraction utility

Use `scripts/research/extract-manifest.py` to normalize an existing CSV/JSON manifest. It requires explicit source-column mappings and a written `--group-evidence` explanation. It preserves IDs/splits/labels; it does not synthesize group IDs or hashes. A `--path-map` JSON can map exact paths or path prefixes (see `path_map.example.json`).

For byte-level verification, pass both `--verify-images --image-root ROOT`; the extractor then requires every mapped file to exist and recomputes SHA-256 from the actual bytes. Use `scripts/research/audit-phash.py` afterward to calculate a versioned 64-bit DCT pHash and check Hamming-distance near-duplicates. Its `drplant-dct-phash-v1` implementation uses ImageMagick grayscale/Lanczos 32×32 input, 8×8 low-frequency DCT, median thresholding, and a project-selected threshold; the threshold is a review flag, not a universal scientific standard. Without that flag, the result is metadata extraction only and must remain in `staging/`, not be treated as a verified production manifest. A report is written separately for provenance.

The Citrus Field V3 model manifest was normalized to `staging/citrus-field-v3.csv` (610 rows, 14 source `tree_id` values; split counts 332/144/134). Its 610 image files were found in the restored sibling worktree at `/workspace/dr-plant/data/external/2026-11/citrus-field-v3/Field-Based Citrus Leaf Disease Image Dataset/Moroccan Citrus Leaf Dataset`; SHA-256 was recomputed from every file, and the group/hash/image verifier passed. The curated model manifest is tree-held-out (9 train trees, 3 validation trees, 2 test trees), and all 610 files passed ImageMagick decode checking. Important: the separate source `recommended_partition.csv` uses leaf-level `Group_ID` values and distributes trees across splits (13 tree IDs span multiple splits); its tree-disjoint audit fails and it is not the split used by the trained candidate. One metadata/path conflict (`IMG_0405`, metadata T07 vs path T08) was quarantined upstream. This is a file-verified research manifest for exact SHA and tree isolation, not local Syrian validation or production approval. The separately versioned perceptual near-duplicate/pHash audit is complete for Citrus and returns FAIL due to five candidate pairs, including one cross-split pair; do not call its full leakage gate closed until all candidates are reviewed.
